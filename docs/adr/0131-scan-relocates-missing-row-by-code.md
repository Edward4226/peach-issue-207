# ADR-0131：扫描时按番号把文件已不在的在库行改指到新文件

- 状态：已采纳
- 日期：2026-11-03
- 关系：补充 [ADR-0087](0087-vanished-files-keep-personal-records.md) 决策二的触发时机；判据沿用它的番号键

## 背景

[#312](https://github.com/peach-mitao/peach/issues/312) 的报告者把影片目录改了名，同时换了编码。之后先在资源同步里「检查文件」，再跑增量扫描，结果旧行仍指向不存在的旧路径，扫描又登记了一条没有番号的新行，标签、封面与观看记录都留在旧行上。

已有两条接回路径都没有生效：

- 文件身份（`file_identity`）按卷号、inode、大小与修改时间认同一个文件，只覆盖同卷改名或移动。文件换了编码，指纹就对不上。
- ADR-0087 决策二按番号接回，但只在 `disposal='vanished'` 的行里找。旧行要等资源同步「清理」才会被标已消失，「检查」只报数不改。所以「检查 → 扫描」这个顺序下，扫描登记新文件时还没有可接的旧行。

即使之后再清理，接回也只搬个人记录；刮削来的标签、封面和资料留在旧行快照里，新行要从头刮削。不带个人记录的旧行会被直接删除。

## 决策

扫描与推送发现登记一个还没有账本行的视频之前，先按文件身份接回；接不上时，再由 `record_rehome.CodeRelocator` 按番号判断。以下条件全部成立，就把旧行的 `path`、`name` 改成新文件，不新建行：

1. 新文件名解析出番号（`normalise_code_key`），并且新文件所在目录里这个番号的视频只有它一个。
2. 同一扫描根下，这个番号的在库视频（`disposal IS NULL`）恰好一条。
3. 这条旧行的路径 `stat` 明确返回「文件不存在」。读取失败、超时或权限错误都不算。

旧行的 id、标签、封面、资料与个人记录原样保留。探测列（时长、分辨率、编码等）清空，等探测补上。增量扫描把这些行并进探测范围，但不并进新影片范围，所以不会触发 `reattach`、想要清单对账、目录规则和「新增」标记。

已标 `vanished` 的行仍按 ADR-0087 决策二接回。同一番号有多条候选、同目录有多个同番号视频，或旧行在别的媒体根下，这里都不处理，仍交给资源同步与 `reattach`。

## 理由

- 番号是跨版本稳定的键（ADR-0087）。旧文件不在、同番号新文件出现，在单人馆藏里几乎就是换版本或整理目录。报告者手工修复的做法也正是把旧行改到新路径，再删掉重复行。
- 只在同一扫描根里找：别的媒体根可能只是没挂上，那里的 `stat` 同样会返回「不存在」，不能当作文件已删除。
- 这一步不记 ADR-0052 批次，与文件身份接回一致。改指只改路径定位，没有写入新的真相字段；旧路径已不存在，撤回后会指向一个打不开的文件。资料与个人记录都没有移动，不需要快照。

## 被否决的方案

- **扫描时把没标 `vanished` 的旧行也纳入 `reattach`。** `reattach` 会搬走个人记录、删除旧行，刮削标签与封面照样丢失，没有解决报告里的主要损失。
- **「检查文件」顺带标 `vanished`。** 检查只读盘、不改任何东西（[运行与配置](../OPERATIONS.md)「资源同步」），用户确认清理之前不该有写入。
- **按番号加时长判断。** 登记时新文件还没探测，拿不到时长。同目录只能有一个同番号视频、同根只能有一条同番号候选，这两条已经排除了分卷与多版本并存的情况。

## 后果

- `ScanResult.relocated_ids` 与 `IngestResult.relocated` 记录被改指的行，库处理的增量扫描据此补探测。
- 预览帧、九宫格等派生产物的来源签名含路径与文件代际，改指后自然失效，会重新生成。
- 同目录里旧字幕的 `asset_subtitle` 行不随之迁移，新目录的字幕会在扫描时重新配对。这一点与文件身份接回相同。
- 网盘目录若偶发对单个文件答「不存在」，同时同番号的新文件刚好出现，旧行会被改指到新文件；之后旧文件再被扫到时，会登记成一条新行。

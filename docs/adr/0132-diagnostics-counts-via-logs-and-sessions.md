# ADR-0132：技术诊断的计数改走日志与会话

- 状态：已采纳
- 日期：2026-11-03
- 相关：ADR-0109、ADR-0110

## 背景

ADR-0109 让版本统计和故障计数都以 Sentry 错误事件发送。托管服务的错误事件按条计费，免费档有月度上限。实际运行中，上限在计费周期开始两天内就被耗尽，之后的事件全部被拒收，新故障也看不到了。事件的主要来源有三类：

- 每台机器每天一条版本统计；
- 同一台机器上的同一个故障，每个 UTC 日都重新上传一次「首次」，之后每小时再补一批增量次数；
- 设计上应留在本机的预期失败，因为筛选判据有漏项而被上传。

免费档不提供按版本或消息的入站过滤、按密钥限流或数据转发，接收端没有可用的开关，只能由客户端少发。

## 决策

错误事件只承载需要定位的诊断：带异常链和代码位置、按问题归组的那一条。计数和统计改用不按条计费的两种数据：

1. **版本统计**：每天一次，改发一条 Sentry 日志（`log` 条目，属性沿用原版本统计字段），再加一条会话汇总（`sessions` 条目，只含版本与运行环境，记为一次正常结束）。会话汇总让接收端的 Releases 页显示各版本占比。会话不在托管服务的计费类别里；日志按字节计费，额度与错误事件分开。
2. **故障计数**：同一台机器上同一个诊断键（脱敏技术字段的哈希，包含版本）只上传一次错误事件；之后的发生次数累计在本机，每 6 小时或正常退出时合并成计数日志，属性带 `diagnostic_key`、`occurrence_day` 和整数 `occurrence_count`，接收端可以直接按日期和版本求和。诊断键连续 7 天没有再发生，本机记录过期；再次发生时重新上传一次错误事件。每机每天最多上传 5 条首次错误事件，新出现的诊断键每天最多登记 20 个。
3. **筛选判据补漏**：坏媒体与读写错误、文件锁争用、SQLite 磁盘与锁错误、媒体子进程超时、来源连接超时、路由主动返回的 502–504，以及读取方已断开时的管道写入失败，都留在本机。

日志和会话条目由 Peach 自己组装成信封，不经过 SDK 的日志批处理器和会话追踪，因此 SDK 默认附加的主机名、SDK 名称和追踪上下文不会进入载荷。两类条目和错误事件走同一个传输闸门：发送前复查本机同意版本，关闭后排队的条目失效；测试模式下同样在最终 HTTP 边界阻止外发。

## 代价

- 接收端的问题列表不再反映发生次数；频率要在日志查询里按 `diagnostic_key` 汇总。
- 日志条目不归组、不触发问题告警，免费档只保留约 30 天。
- 同一故障在一台机器上每个版本只报一次，修复验证要看计数日志是否归零，不能只看问题是否出现新事件。
- 已安装的旧版本仍按旧节奏发送，直到用户升级。必要时可以在新版本换用新的接收密钥，待新版普及后停用旧密钥。

同意范围不变：两类数据仍由「版本统计与错误诊断」开关控制，字段白名单不扩大。[日志与诊断核验](../DIAGNOSTICS.md#可选远程诊断)同步改写了节奏和查询口径。
